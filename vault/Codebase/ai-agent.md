# AI Agent

## Overview

`src/lib/ai` הוא העוזר שמדבר עם המשתמש ב-Telegram: OpenAI עם tool calling, שמתרגם
עברית חופשית לפעולות במערכת.

שתי החלטות מבניות קובעות כמעט כל שורה במודול.

### 1. ל-agent אין גישה ל-Firestore

כל קריאה וכתיבה יוצאות ב-**HTTP אל `/api/v1`**, נושאות Firebase ID token של אותו
משתמש. הקיצור המתבקש — לקרוא ישירות ל-`@/services/server` — היה חוסך import אחד
ומוציא את ה-agent **מחוץ** לכל הבטחה שה-API נותן. דרך ה-endpoints הוא יורש את
`requireUser`, את סכמות ה-Zod, את `assertReferencesOwned` ואת כלל 404-ולא-403,
בלי מימוש שני של אף אחד מהם.

הטוקן **נטבע, לא מושאל**: הודעת Telegram אינה נושאת שום credential. `createCustomToken(uid)`
ב-Admin SDK, ואז החלפה מול Identity Toolkit ל-`idToken` שאינו נבדל מזה שדפדפן היה
מחזיק. נשמר במטמון ל-50 דקות.

### 2. פעולה משנה לעולם לא רצה בתור שיצר אותה

`create_task` / `update_task` / `delete_task` מוצהרים ב-`AGENT_TOOLS` אבל
**נחסמים ב-loop**: נבנית תצוגה מקדימה בעברית, הפעולה נשמרת כ-`pendingAction`,
והתור נעצר. רק "כן" מפורש (כפתור inline או מילת אישור) מגיע ל-`executeTool`.

לכן אי אפשר "לשכנע" את המודל לדלג על האישור — **המודל אינו מי שמחליט להריץ**.
התצוגה המקדימה נבנית מה-**ארגומנטים**, לא מהפרוזה של המודל: מודל שאומר "אעדכן
לגבוהה" ומעביר `urgent` נתפס על ידי האדם שקורא.

### מפת הכלים

| כלי | סוג | דרך |
|---|---|---|
| `list_tasks` | קריאה | `GET /tasks` + סינון `due` בזיכרון |
| `get_task` | קריאה | `GET /tasks/{id}` |
| `get_dashboard` | קריאה | `GET /tasks` + צבירה (מראה את `useDashboardStats`) |
| `list_projects` / `list_tags` | קריאה | `GET /projects`, `GET /tags` |
| `create_task` | **אישור** | `POST /tasks` |
| `update_task` | **אישור** | `PATCH /tasks/{id}` |
| `delete_task` | **אישור** | `DELETE /tasks/{id}` |

**שמות, לא מזהים, באוצר המילים של המודל.** מודל שפה לא יכול לדעת מזהה Firestore,
ודרישה שישלוף אחד לפני כל כתיבה הופכת משפט אחד לארבע קריאות שאפשר לטעות בהן.
פרויקטים ותגיות מטופלים לפי שם ונפתרים מול הרשומות של המשתמש עצמו; התאמה חלקית
שמחזירה כמה תוצאות נחשבת **אי-התאמה**, כי לפעול על "שיווק" מעורפל זו הטלת מטבע.

## Files

| קובץ | מה הוא עושה |
|---|---|
| `src/lib/ai/api-caller.ts` | טביעת ID token לכל uid, מטמון, ו-`AgentApiClient` שקורא ל-`/api/v1` ומחזיר `AppError` על כישלון. `resolveSelfOrigin` בוחר `APP_BASE_URL` או origin הבקשה |
| `src/lib/ai/date-zone.ts` | המרות `YYYY-MM-DD` ↔ ISO **באזור הזמן של המוצר** (`Asia/Jerusalem`). `@/utils/date` עובד באזור של הדפדפן, וכאן רץ שרת — לרוב UTC |
| `src/lib/ai/tools.ts` | הגדרות הכלים, `ToolContext` (מטמון פר-תור לפרויקטים ותגיות), `executeTool`, `buildActionPreview`, `describeCompletedAction`, `MUTATING_TOOLS` |
| `src/lib/ai/prompt.ts` | ה-system prompt. כתוב **אנגלית** בעוד התשובות עברית — ציות להוראות חזק יותר, ופחות סיכוי שהודעת משתמש תיקרא כהוראה |
| `src/lib/ai/agent.ts` | `runAgentTurn` (ה-loop) ו-`applyPendingAction` (הרצה אחרי אישור) |
| `src/lib/ai/index.ts` | barrel, `server-only` |

### פרטים שקל לפספס

- **ההיסטוריה שומרת רק תורות טקסט נקיים.** קריאות כלים ותוצאותיהן נזרקות ולא
  נחתכות: ה-API דוחה הודעת `tool` שההודעה שיצרה אותה חסרה, ולכן "שמור את ה-N
  האחרונים" היה בסופו של דבר חוצה זוג ומפיל את הבקשה ה**באה** — באג שמופיע רק
  אחרי ששיחה מתארכת.
- **`dateOnlyToIso` עושה שני מעברי תיקון.** מעבר אחד קורא את ההיסט בחצות UTC,
  שביום מעבר שעון הוא ההיסט של הצד הלא נכון — ב-2026-03-27 ישראל מקדמת ב-02:00
  מקומי שזה בדיוק 00:00 UTC, והניחוש היה נוחת ב-23:00 בערב הקודם.
- **`shiftDateOnly` הוא אריתמטיקה קלנדרית טהורה.** הוספת `days * 86_400_000`
  שגויה סביב מעבר שעון, שבו יום אזרחי הוא 23 או 25 שעות.
- **הפעולה הממתינה נמחקת לפני שהיא רצה**, לא אחרי — אחרת קריסה הייתה משאירה
  פעולה מאושרת דרוכה, וניסיון חוזר היה מחיל אותה פעמיים.
- **`totalMatched` מוחזר לצד `tasks`** כדי שהמודל יידע שהוא מסתכל על תצוגה קטומה
  ולא יענה "יש לך 25 משימות" כשיש שמונים.
- **הודעה שאינה כן/לא כשיש פעולה ממתינה מבטלת אותה** — המשתמש המשיך הלאה, ולא
  נכון להשאיר פעולה דרוכה מאחורי שיחה אחרת.

## Open Questions
- המודל ברירת המחדל הוא `gpt-4o-mini` דרך `OPENAI_MODEL`; לא נמדדה איכות ההבנה
  בעברית מול מודל גדול יותר.
- הכלים מכסים משימות בלבד. יצירה/עריכה של פרויקטים ותגיות אינה חשופה ל-agent.
- אומת מקצה-לקצה מול OpenAI אמיתי ב-2026-08-06 בפרודקשן.
- **שיחות שנוצרו לפני התיקון של 06-08 עדיין נושאות את התצוגות המילוליות** בהיסטוריה
  וימשיכו לשחזר אותן עד `/reset`. לא נכתבה מיגרציה — המחיר הוא איפוס שיחה.
- `MAX_ITERATIONS = 5` נבחר בהערכה; לא נמדד כמה תורות בקשה טיפוסית באמת צורכת.
- אין תקרת עלות מצטברת פר-משתמש, רק `RATE_LIMITS.aiTurn` (30 לחמש דקות).

### 2026-08-06 — ה-agent חיקה את תצוגת האישור של עצמו [shipped]
- **What was done:** אובחן ותוקן באג התנהגותי. התסמין: כל בקשת "תיצור משימה" קיבלה
  תצוגה מקדימה שנראית תקינה, אבל «כן» החזיר את אותה תצוגה שוב ושום משימה לא נכתבה.
  האות המכריע היה ב-Firestore: `pendingAction: null` בשיחה שהתגובה האחרונה בה
  **הייתה** תצוגה מקדימה — מצב שאפשרי רק דרך הענף `toolCalls.length === 0`, כלומר
  המודל לא קרא לשום כלי. הסיבה: בתור אישור נשמר טקסט התצוגה **כלשונו** כהודעת
  assistant בהיסטוריה, ובכך ניתנה למודל דוגמה מתויגת של "ככה אני עונה על בקשת
  שינוי". מהתור הבא הוא הפיק את הטקסט ישירות במקום לקרוא ל-`create_task` — ובלי
  קריאת כלי אין `pendingAction`, ולכן ל«כן» לא היה מה לאשר. כל חיקוי הוסיף דוגמה
  נוספת, ולכן הכשל הזין את עצמו. ההיסטוריה שומרת כעת הערה פנימית
